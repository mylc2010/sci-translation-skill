# Reader-oriented editing without scientific drift

在忠实首译后使用。借鉴 nature-polishing 的类型/章节路由、先诊断后润色和读者路径，改造为翻译约束下的编辑；无需安装或加载另一 skill。
读者路径是让作者已有论证更易理解，不是替作者增加新论证。原文与冻结词表始终优先。

## 1. 轻量语境卡与诊断

示例：`type=algorithmic; section=abstract; audience=security researchers; journal=unspecified; scope=within-paragraph`。
论文类型可为实证研究、方法/系统、综述、假说等；只依已给内容判断，不为短段强行分类或生成完整论文大纲。
未指定读者时采用本领域学术读者，不擅自为跨学科读者补充教科书解释。

按以下顺序诊断，仅加载/使用相关章节规则：
1. 章节承担什么任务？问题是原稿缺证据，还是英文组织不清？
2. 原文有哪些命题、对比、条件及证据？能否建立可追溯的信息顺序？
3. 哪些句子存在主语漂移、指代不明、过多动作或嵌套？
4. 最后才考虑动词、词序、句长和标点。

无证据的贡献、缺失的机制解释和相互矛盾的条件只列作者问题；不得用流畅句子掩盖它们。
需要跨段移动、删减实质内容、增加定义或重构章节时，先给建议并取得作者授权。未授权时仍交忠实译文。

## 2. 章节任务：组织已有信息，不补齐模板

| 章节 | 优先帮助读者看清 | 不允许的自动操作 |
|---|---|---|
| Abstract | 问题/缺口→方法→主要结果→原文已有的结论；合适时合并同条件下的并列指标 | 为凑五步补意义、删原文背景或局限；把经验表现升级为保证 |
| Introduction | 已知情况、实际需求、具体缺口和本文回应之间的关系 | 扩大已有工作不足、补“首次”、重写贡献范围 |
| Methods / system | 系统是什么→各主体如何执行→输入/输出及条件；分清信任边界 | 擅补算法步骤、把流程先后写成因果、把部分解密写成用户已获明文 |
| Results | 条件/对象→观察→比较；指标与对应条件紧密绑定 | 把观察改成解释或因果；删除源文中的解释以强制“纯结果” |
| Discussion / conclusion | 原文支持的解释、意义、限制和适用边界 | 新增应用前景、抹除局限或将条件性结果普遍化 |
| Review / hypothesis | 文献归属、综合判断与未验证假说的区别 | 将他人的结论据为本文贡献或把假说改成已验证事实 |

全文终稿可在已有审校里做一次轻量跨章节核对：引言的问题与贡献是否能定位到结果证据，摘要主结论是否保持正文的对象、条件和数值边界，讨论中的解释和局限是否指向其实际约束的结论。重复结果与必要的讨论回顾要按句子作用区分，不机械删除。若中文原稿本身缺少对应证据、存在章节矛盾或局限写得过泛，只列作者问题；翻译者不能自行补实验、压缩为“一个主发现”、删减次要结果或重排章节。此核对只用于全文任务，不给独立短段增加额外流程。

章节混杂可提出建议，但翻译仍保留原有命题。时态由事实性质决定：已执行实验通常过去时，系统属性可现在时；不整章机械替换。
字数上限只采用作者明确要求或已核验要求。若保留所有命题无法达到限制，报告冲突并提出可选删减，未经授权不提交“已满足”的缩水稿。

## 3. 句内负荷与段内衔接

- **明确主体**：一句涉及多个主体时，考虑在主体切换处断句。保持“云进程、飞地、用户”或“患者、研究者、模型”的职责和边界，不把环境名替成新执行者。
- **信息递进**：先提供理解后句所需的信息，再展开新内容；句首可承接上一句的实体，但不机械重复固定句式。
- **明确指代**：this/it/which 有多个候选对象时，用已锁定的技术名词或准确概括替代，不为避免重复换术语。
- **保留依存关系**：拆句时让 only、may、under、compared with 等仍约束原命题；引用仍支持原断言。不得将“同时”改为新因果。
- **句长软诊断**：约 30 词以上可检查负荷，不自动扣分或拆句。长正式名称、公式和不可分条件可能需要长句；短于 10 词也合法。
- **自然节奏**：保留可读的短句；合并碎句须有真实逻辑关系，不能新增 therefore 或 hence。标点以清晰为准，不禁用破折号或分号。

方法/系统段尤其区分三类命题：组件及目标、机制与执行过程、评估及边界。允许同段改写来澄清它们，不强制每类独立成句或重排用户固定结构。

## 4. 编辑后的双向回查

完整文件任务保留首译与编辑稿的差异；短段只需简短命题对照。
Reviewer 先检查原文↔编辑稿，再检查首译→编辑稿，不能只证明新稿“比旧稿好读”。
每次拆合句重点复核主体、否定/量词、条件、因果强度、数值/指标、引用及核心术语；任何新引入的技术偏移都须回退或修正。
对 STYLE 建议给出具体阅读障碍和改后效果；若只是个人喜好，标 optional，不算原稿错误。

## 5. 构造示例（不是效果评测）

### 主体和条件一起拆清

源文：“仅在半诚实云假设下，过滤器筛选候选，飞地验证访问结构，而授权用户解封装数据密钥；尚未评估恶意云。”

可译：“Under the semi-honest cloud assumption, the filter selects candidates and the enclave verifies the access structure. Authorized users then decapsulate the data key. These steps are specified only under that assumption; a malicious cloud has not yet been evaluated.”

末句明确整个步骤的适用条件，是为了防止拆句后作用域漂移；实际稿件若可无歧义地写得更紧凑，不必照抄。
不可译：“The filter ensures secure retrieval. Users then decrypt the documents.” 这增添安全保证并改变操作对象与动作。

### 数值与比较关系不因流畅而改变

源文：“在 37 °C 下，A 的误差为 2.1%，B 为 3.4%；尚未测试其他温度。”
可译：“At 37 °C, the errors for A and B were 2.1% and 3.4%, respectively. Other temperatures have not yet been tested.”
不可改成“A consistently outperformed B.”；不能把 2.1%/3.4% 互换，也不能省去温度限制。
