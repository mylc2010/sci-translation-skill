# Behavioral evaluation protocol

规则与静态测试通过不等于翻译达到投稿水平。用同一模型/设置、相同原文与已确认词表比较版本；
隐藏版本标签，让不参与首译的 Reviewer 对照源文评价。多次独立运行再看稳定性，不从一段推断所有学科。

## 维度和放行规则

优先判技术含义、论断强度、术语、遗漏/新增、数据绑定、结构/LaTeX，再比较自然度与简洁性。
记录实际错误例句和严重度；任一未解决 critical/major 不可因文风总分高而放行。
建议每领域覆盖方法/结果/摘要、跨段术语和长文接缝。医学需领域人员终审；程序测试不能替代。

## 最小案例集

1. CS：初步实验可能表明，仅在半诚实模型下有效；未测试恶意服务器。保留全部限定。
2. CS：同句既有 KEM 解封装又有载荷解密。不能全局禁止 decryption。
3. CS：LSSS 访问结构与系统访问策略并存。不要全部替换为 structure。
4. Medicine：回顾性队列、关联性陈述、样本量、效应量/区间/单位/时间点。不能增加因果或显著性。
5. Engineering：仅在指定温度与负载下的误差范围。不能变为普遍适用。
6. LaTeX：同数目的公式但符号被改；重复引文被删；数字没有变化但归属被交换。
7. Structure：长表格单元格被移到表外、表格坐标变动、跨块代词无指向。
8. Runtime：没有团队工具时必须串行披露；有工具时记录真实 ID，不能模拟多 Agent 日志。
9. Source defect：只有“图1”但未给标签；不能编造 \ref。原文“可能证明”有张力时保留并提 query。
10. Revision：初稿正确但修订引入新错误；终稿复核必须能重新打开 issue。

## 测试报告

列出输入、实际输出、角色/模型（已知时）、采样设置（已知时）、发现与修正、剩余问题。
“未验证”应明确出现；不把教学例句写成实测结果，不冒充医学/跨平台认证。
