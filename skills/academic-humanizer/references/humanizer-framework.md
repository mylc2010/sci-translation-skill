# Humanizer framework for academic prose

The complete upstream instructions, rationale, examples and original source are in [upstream-humanizer.md](upstream-humanizer.md), reproduced under the bundled [MIT license](../HUMANIZER-LICENSE). This reference is an academic, report-driven adaptation: preserve meaning and retain the review gate even if the upstream file-mode instructions suggest direct editing.

The upstream framework groups 26 checks into six areas:

1. Staging instead of stating: unnecessary not-X-but-Y contrasts; redundant one-line closers; sayings posing as insight; staged run-ups; arguing against claims nobody made (1–5).
2. Rhythm by rule: forced triads; repeated sentence openings; indiscriminate dashes; stacked qualifiers; repeated hyphenated pairs; passive voice/missing subject (6–11).
3. Inflation and borrowed authority: overused AI words; inflated significance; vague association; shallow -ing phrases; sales language; borrowed authority; avoiding is/are/has (12–18).
4. Formatting by rule: decorative bold, headings, quotation marks (19–21).
5. Draft leftovers: chatbot residue; knowledge-limit boilerplate; headings repeated in first sentences; writing about the document instead of the subject (22–25).
6. Wrong reader: re-explaining shared context (26).

The upstream method is diagnose structural tells, draft, check all facts and scope, then read for remaining patterns and voice. The strongest tells can justify an edit when genuinely present; weaker signals need context. No word, passive voice, triad, necessary contrast, author voice, scientific limitation or properly hedged statement is automatically a defect. Exclude formulas, figures, tables, captions, code and references from this skill's edits even where upstream instructions would otherwise permit them.
